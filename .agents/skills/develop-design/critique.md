# Independent design critique

Used by [develop-design](SKILL.md). Capture and inspect the current rendered design first. A code review is not a visual critique. For interactive behaviour, include appropriate state captures or inspected recordings and observed behaviour; state what a screenshot cannot prove.

Start a fresh-context critic with the brief, fixed constraints, actual current evidence and relevant quality references. Do not inherit builder conversation, code, implementation effort, justifications, prior scores or critique history. Supply readable image paths or actual images and require the critic to inspect them. If reference access fails, resolve it before claiming reference-based judgement.

## Critic brief

“Review the attached rendered design against this brief and its fixed constraints. Use the supplied references as a quality baseline, not a layout to copy. Identify the most consequential gaps in identity, composition, hierarchy, typography, task clarity and relevant interaction evidence. For each, name the location/state, observable problem, effect and concrete improvement. Distinguish taste from usability and uncertainty from evidence. A successful design may need no changes. Do not invent defects to fill a quota or infer behaviour from still images.”

The builder assesses feedback against the brief, records accepted/rejected consequential suggestions with reasons, makes changes and captures again. Each new round gets a fresh critic without earlier critique history. Keep the same criteria unless the user's direction changes.

Default to at most two autonomous critique-and-change rounds per batch. At that boundary compare observed progress: stop when remaining issues are local or feedback repeats; ask when taste is unresolved; return to ideation if the concept is failing. Continue another bounded batch only for material progress within authority. A score cannot establish completion or trigger endless retries.

If subagents are unavailable, disclose that independence is unavailable and offer sequential review. When that fallback is already authorised, proceed with a separate review pass labelled as self-review; otherwise wait for the user's choice. Preserve the same criteria and limits without claiming fresh-context independence.
