# Humanise copy

Runs separate, inspectable editing passes without flattening the writer’s personality.

## When to use

- Editing supplied copy to improve clarity or reduce generic writing habits.
- Not for determining AI authorship, inventing personal experiences or rewriting approved wording unnecessarily.

## Inputs

- Text, audience, format, intended action and relevant voice guidance or approved examples.

## Steps

1. Read the full text and [editing.md](editing.md). Use existing copywriting guidance and relevant approved samples. Ask for missing text; ask about audience or purpose only when ambiguity would change the edit.
2. Identify meaning, facts, action semantics and voice traits to protect, including humour, bluntness and uncertainty. For interface copy, preserve what actions and states actually do.
3. Save the original. Perform the broad-pattern pass and retain that intermediate version with a short change summary.
4. Perform the focused-pattern pass separately. Show its changes separately so the user can undo either pass. Leave strong, distinctive lines alone.
5. Compare both passes with the original for semantic drift, lost personality, invented facts and changed promises. Correct drift; flag unresolved claims rather than inventing specifics. Offer optional read-aloud review of prominent lines.
6. Return edited text, attributable changes and uncertainties. In a design exploration, link versions in its existing record; standalone editing needs no design domain or exploration setup.

## Done when

- Both passes are reviewable and preserve facts, functional meaning and supported voice.
- Uncertainty is flagged; human editorial review is not claimed unless performed by the person.
