# Refine a design

Resolves an established direction through distinct, reviewable finishing passes.

## When to use

- Finishing a developed design at an agreed fidelity.
- Not for imposing a new creative direction or publishing.

## Inputs

- The design, intended endpoint, criteria, exploration record and relevant design/copywriting guidance.

## Steps

1. Recover context using the shared [workflow](../design-with-ai/workflow.md); inspect the current rendered experience. Resolve major concept questions through [develop-design](../develop-design/SKILL.md), without restarting intake.
2. Read [refinement.md](refinement.md). Apply a subtraction pass, then contextual visual-pattern review. Retain versions and distinguish changes by pass.
3. Use [humanise-copy](../humanise-copy/SKILL.md) for copy that needs editing, carrying its functional meaning and voice constraints. Offer prominent lines for optional human read-aloud/editing; do not block already-authorised work on an optional exercise.
4. Resolve typography, spacing, assets, responsive layouts and applicable loading, empty, error, focus and interaction states. For motion, use [media guidance](../develop-design/media.md).
5. Verify the actual experience against the requested endpoint, using [verify-work](../verify-work/SKILL.md). Separate visual inspection, functional checks and remaining accessibility limitations. Do not claim compliance from screenshots.
6. Compare before and after, undo changes that weaken purpose or identity, and repeat only where unresolved criteria justify it. Update the record and approved project guidance; leave experiments provisional.

## Done when

- Agreed quality criteria are supported by appropriate evidence.
- Passes are reviewable, functional meaning is preserved, and limitations or remaining decisions are stated.
- Finishing has not silently expanded to publishing or production readiness.
