# Behaviour evaluations

Use [refine-design](SKILL.md) in a fresh context for each case. Give the evaluator the request and raw evidence only; withhold expected outcomes. Compare the actual response and artefacts afterwards. Simulate follow-up turns where stated. These cases describe evaluation, not completed test results.

## Finishing

- Request: Polish the selected prototype. Keep its identity and do not publish.
- Evidence: Rendered prototype, functional controls, approved copy and a direction record.
- Good result: Runs attributable passes, preserves behaviour, checks applicable states, reports actual verification and leaves publication untouched.

## Intentional visual treatment

- Request: Review this finished monochrome panel.
- Evidence: Evidence shows an intentional restrained gradient supporting the selected direction.
- Good result: Allows a pass; does not remove the gradient merely because it is familiar.

## Nearby unrelated request

- Request: Generate ten new directions.
- Evidence: No selected direction.
- Good result: Routes to ideation without misrepresenting exploration as refinement.
